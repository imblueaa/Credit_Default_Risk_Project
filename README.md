# Credit Default Risk Prediction

## صورت‌بندی مسئله

مسئله یک **Binary Classification + Probability Estimation** است.

هدف، تخمین احتمال نکول ماه آینده و سپس استفاده از آن احتمال برای اولویت‌بندی بررسی انسانی است.

### هزینه خطا

در پروژه فرض شده است:

- هزینه `False Negative = 5`
- هزینه `False Positive = 1`

یعنی از دست دادن یک مشتری واقعاً پرریسک، پنج برابر هشدار اشتباه برای یک مشتری کم‌ریسک هزینه دارد.

بنابراین Accuracy معیار اصلی نیست و **Average Precision / PR-AUC** به‌عنوان معیار اصلی رتبه‌بندی انتخاب شده است.

## آماده‌سازی داده

ستون `ID` از ورودی مدل حذف شده است.

متغیرهای دسته‌ای مانند:

- `SEX`
- `EDUCATION`

- `PAY_0` تا `PAY_6`

به‌صورت categorical پردازش شده‌اند و به‌صورت عدد پیوسته تفسیر نشده‌اند.

پردازش‌ها در `Pipeline` و `ColumnTransformer` قرار گرفته‌اند تا تبدیل‌ها فقط از داده آموزش یاد گرفته شوند.

تمام این ویژگی‌ها فقط از اطلاعات موجود پیش از هدف ساخته شده‌اند و از خود Target استفاده نمی‌کنند.

## مدل‌ها

سه سطح مدل مقایسه شده‌اند:

### 1. Dummy Classifier

به‌عنوان خط پایه برای مشخص کردن اینکه مدل‌های واقعی چقدر بهتر از پیش‌بینی مبتنی بر نسبت کلاس‌ها عمل می‌کنند.

### 2. Logistic Regression

مدل تفسیرپذیر خطی.

### 3. Random Forest

مدل غیرخطی اصلی پروژه.

نتایج Validation:

| Model | PR-AUC | ROC-AUC | Brier |
|---|---:|---:|---:|
| Dummy | 0.2212 | 0.5000 | 0.1723 |
| Logistic Regression | 0.5382 | 0.7677 | 0.1826 |
| Random Forest | 0.5515 | 0.7811 | 0.1744 |

Random Forest در معیار اصلی Validation بهترین عملکرد را داشته است.

## Calibration

بعد از تنظیم مدل، از:

استفاده شده است.

این بخش مهم است زیرا خروجی مدل فقط یک کلاس نیست؛ بلکه یک احتمال است و احتمال باید تا حد امکان با نرخ واقعی نکول سازگار باشد.

## انتخاب آستانه تصمیم

آستانه 0.5 به‌صورت پیش‌فرض پذیرفته نشده است.

آستانه با استفاده از Validation و تابع هزینه زیر انتخاب شده است:

```text
Cost = 5 × FN + 1 × FP
```

آستانه نهایی:

**0.145**

مقایسه Validation:

| Threshold | Cost | Review Rate | Recall(Default) | Precision(Default) |
|---:|---:|---:|---:|---:|
| 0.145 | 3255 | 47.07% | 77.92% | 36.61% |
| 0.500 | 4471 | 11.63% | 35.95% | 68.34% |

تفسیر:

- آستانه 0.145 افراد بیشتری را برای بررسی انسانی معرفی می‌کند.
- در عوض، Recall کلاس نکول به شکل محسوسی افزایش می‌یابد.
- این انتخاب با هزینه بالاتر False Negative سازگار است.

## Genetic Algorithm Feature Selection

الگوریتم ژنتیک به‌عنوان بخش مستقل و الزامی پروژه اجرا شده است.

کروموزوم، حضور یا عدم حضور ویژگی‌های اصلی را نمایش می‌دهد.

تنظیمات:

- Population = 16
- Generations = 8
- Elitism = 1
- One-point crossover
- Mutation rate = 0.08
- Minimum features = 4
- Seeds = 11, 22, 33

دو سناریو بررسی شده‌اند:

1. با متغیرهای حساس جمعیت‌شناختی
2. بدون متغیرهای حساس

Fitness:

```text
Validation PR-AUC - 0.005 × (number of selected features / total features)
```

یعنی تعداد ویژگی‌ها نیز در تابع برازندگی جریمه شده است.

پایداری انتخاب ویژگی با **Jaccard Similarity** بین Seedها بررسی شده است.

نتیجه مهم: زیرمجموعه GA در مقایسه با همه ویژگی‌ها کاهش مختصری در PR-AUC ایجاد می‌کند؛ بنابراین GA در این آزمایش بیشتر برای **کاهش پیچیدگی و بررسی proxy/sensitive features** ارزش دارد تا افزایش امتیاز خام.

## Final Test Evaluation

پس از قفل شدن مدل، Hyperparameterها و Threshold، Test فقط یک‌بار برای ارزیابی نهایی استفاده شده است.

نتایج:

| Metric | Test |
|---|---:|
| PR-AUC | **0.5532** |
| ROC-AUC | **0.7791** |
| Precision(Default) | **0.3592** |
| Recall(Default) | **0.7664** |
| F1(Default) | **0.4892** |
| Macro F1 | **0.6092** |
| Brier Score | **0.1359** |
| Threshold | **0.145** |
| Review Rate | **47.18%** |
| Cost | **3364** |

Confusion Matrix:

```text
TN = 2859
FP = 1814
FN = 310
TP = 1017
```

نکته مهم: Recall کلاس نکول حدود **76.6%** است؛ یعنی مدل بخش بزرگی از مشتریان واقعاً نکول‌کننده را برای بررسی شناسایی می‌کند، اما در مقابل False Positive قابل‌توجهی دارد. این دقیقاً همان trade-off مورد انتظار در یک مسئله هزینه‌محور است.

## مهم‌ترین نتیجه پروژه

مدل نهایی نشان می‌دهد که می‌توان با استفاده از سابقه پرداخت و اطلاعات مالی، احتمال نکول ماه آینده را با عملکردی بهتر از خط پایه برآورد کرد.

با این حال:

- از Accuracy به عنوان معیار اصلی استفاده نمیشود.
- و Threshold برابر 0.5 الزاماً تصمیم مناسبی نیست.
- احتمال مدل باید Calibration شود.
- نقاط پرت نباید بدون دلیل حذف شوند.
- از Test نباید در انتخاب مدل یا  Threshold استفاده شود.
- اختلاف زیرگروه‌ها باید ممیزی شود.
- مدل نباید برای قبول یا رد خودکار اعتبار استفاده شود.

بنابراین خروجی نهایی باید به شکل زیر تفسیر شود:

> **Predicted probability → Risk prioritization → Human review**

و نه:

> **Predicted probability → Automatic credit approval/rejection**

## نتیجه نهایی

این پروژه یک Pipeline نسبتاً کامل و leakage-aware برای پیش‌بینی ریسک نکول ارائه می‌دهد که شامل:
